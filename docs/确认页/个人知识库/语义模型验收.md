模型资源大小与运行依赖、应用安装包大小、内存占用分别计量。模型权重不提交，也不内置本次构建产物；许可来源见[第三方许可说明](../../第三方许可/来源说明.md)。

CPU 编码使用 ONNX Runtime 1.31.0、tokenizers 0.23.3、numpy 2.5.4，最多四个算子线程。按 BGE 的 CLS pooling 与 L2 归一化输出 512 维向量，最多 512 token；查询增加官方中文检索前缀。正文按 360 字符、步长 300 切块，保守控制中文长度。SQLite 分批扫描向量，关键词和语义候选按秩融合；每来源只保留最相关片段，最终最多发送五段摘录。

本机 Windows 11 10.0.26200 x64、Intel64 Family 6 Model 154 Stepping 3、Python 3.13.14：16 条合成中文知识、16 个同义问题，预期来源 top-1 命中 **16/16**；4 个无关问题最大余弦分数约 0.329／0.343／0.340／0.473。正例最低约 0.514，据此初定语义阈值 **0.50**。这是同一小样本上的阈值标定，没有独立测试集，不能视为生产准确率或无误召回保证。

一次开发后台测量：热查询编码中位数 **2.51 ms**、最大 **3.03 ms**，冷加载加 16 条短文编码 **124.67 ms**。计时不含构造器原生库导入、数据库扫描、界面与生成服务；CPU 调度会使重测数值波动。全库检索线性扫描，尚未验证大型真实知识库的整体延迟和峰值内存。

开发与 PyInstaller 冻结后台均在临时数据目录、stdin 持续开启的真实协议形态下验证：握手 → 保存合成知识 → 离线索引 → 同义问题命中 → 记忆计数 → EOF 正常退出；未配置生成接口，付费调用为零。进程验证曾发现编码线程首次导入 numpy 卡住，已将原生库导入提前到协议读线程启动前，并在开发及冻结后台重测。该修正针对本机复现现象，未将底层原因推断写成已证实结论。

可复现命令（先在隔离目录准备模型，脚本本身不下载）：

```powershell
.venv\Scripts\python.exe scripts/evaluate_semantic.py --model-root artifacts/semantic-evaluation
npm run build:worker
.venv\Scripts\python.exe scripts/evaluate_semantic.py --model-root artifacts/semantic-evaluation --worker build/worker/knowledge-worker/knowledge-worker.exe
```

报告位于忽略提交的 `artifacts/semantic-evaluation/report.json`、`frozen-report.json`，用例在 `tests/fixtures/semantic_retrieval_cases.json`。工程回归覆盖迁移回滚、幂等清空、全库前九条、长文跨批扫描、向量损坏、内容失效、恢复、取消及单次生成边界；具体结果见[实施与验收](实施与验收.md)。

0.13.0 发布重测：实际打包的后台在临时目录通过握手、离线索引、同义命中、记忆计数与 EOF 退出。热编码中位数 2.76 ms、最大 3.82 ms，冷加载加 16 条短文编码 176.15 ms；计时范围与上述开发测量相同，后台调用为零付费。实际打包 EXE 在 PATH 无 Python／Node.js 时启动、重启和偏好保留通过；原生 NSIS 隔离路径测试通过。详情见[安装与发布](安装与发布.md)。

尚未验证干净 Windows／Windows ARM、完整真实安装升级／卸载、真实付费供应商的答案质量、真实 token 节省比例和大型生产库。相似度只表示相关性，不能保证生成答案正确；本轮通过引用校验、证据预算和可见降级控制风险。
