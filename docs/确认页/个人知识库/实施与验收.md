实施顺序为：先建立隔离旧库回归和契约；再增加版本化主题／补充存储与本地索引；接入结构化目录规划和单点学习；最后完成目录／详情交互、安全排版及跨进程回归。本轮仅在隔离数据上验证升级，不读取正式库。

简单说：先保护旧内容，再补后台能力，最后接好界面并验证。

| 场景 | 必须看到的结果 |
|---|---|
| 离线／无 API 本地查找 | 查询不触发模型；能查知识正文、补充和已保留资料；跨常用／在学／归档范围明确 |

## 1. 目的与范围

把已选择的产品方向拆成可验证的开发阶段，优先验证 Windows 打包、文档解析和引用等高风险环节，再完善搜索、积累、分区和统计。

简单说：先确认关键链路能跑起来，再逐步做完整，避免最后才发现装不上或读错文件。

阶段顺序是建议，暂不承诺工期。用户已选择 Windows 11 x64、16GB 内存、无需独显作为验收基准；具体机器、样例与接口尚未落实，不给出未经验证的准确率、速度、最低配置或安装体积指标。

## 3. 主要验收场景

验收围绕实际使用结果，包括正常操作和重要失败情况，不能只证明界面能打开或单元测试通过。

简单说：需要真的拖文件、提问题、点引用、关程序，再打开检查知识还在。

| 场景 | 应观察到的结果 |
|---|---|
| 已有知识换种说法搜索 | 返回相关旧条目，不直接重复创建同概念笔记 |
| 知识库缺少内容 | 成功形成完整学习内容后进入“在学”，标记生成性质 |
| 只缺少一部分 | 原笔记不被覆盖，补充与依据清楚区分 |
| 拖入／选择／粘贴路径 | 都能加入可访问文件；路径错误或格式不支持有明确反馈 |
| 带文件提问 | 回答引用可回到实际页面或段落，混合来源可区分 |
| 严格文件范围中没有答案 | 明确说明无足够依据，不冒充文件结论 |
| 长文总结与多文件比较 | 全文覆盖方式可说明，引用指向对应文件；未覆盖部分明确告知 |
| 扫描 PDF 或部分扫描页 | 根据实际能力识别或提示未识别，不把空文本当完整解析 |
| 资料按需入库 | 未主动保存时会话后不留整份副本；知识保留必要摘录；用户原文件不受影响 |
| 原文件未保留 | 引用仍能查看摘录，完整原文不可用时明确说明 |
| 三条关联推荐 | 分别验证 2＋1、1＋2、0＋3；无关或重复条目不用于凑数 |
| 点击拓展 | 仅成功完整内容收录，重复点击复用；失败可重试 |
| 频率分区 | 新内容在学；14 天内至少 3 个使用日进入常用；收录满 30 天且连续 30 天没使用进入归档；同日去重、重新激活和手动固定符合 A 方案 |
| 未配置 API 或断网 | 仍能浏览本地知识和关键词检索，相关 AI 能力明确不可用 |
| 调用统计 | 生成、拓展、向量化和重试分别记录；未知用量不记零；估算与币种明确 |
| 取消、崩溃和重试 | 界面退出等待；残缺内容不入库；重试不重复保存；已提交结果如实显示 |
| 关闭与重启 | 无孤立后台任务，正式知识持久保存，临时副本按规则清理 |
| 删除与模型切换 | 来源状态和索引同步处理；知识正文保留；不混用不兼容向量 |
| 干净 Windows 安装 | Windows 11 x64、16GB 基准、无需独显和另装 Python，首发约定功能可运行，额外依赖有明确交付方式 |

验收应使用脱敏且允许用于测试的文件；不把模型随机回答完全相同作为通过标准，而检查依据、保存、数量、范围和状态等可验证行为。

### 代表性样例和测量方式

实施时先使用允许测试的公开或人工构造样例，再补充实际常用文档；不要求用户现在提供文件。样例应覆盖中文 MD 的代码与表格、DOCX 标题与表格、普通文字 PDF、双栏长文、清晰扫描、混合扫描页、模糊／倾斜扫描页及两份相关但存在差异的文档。

简单说，用接近日常使用的文件证明“能读对、能找出处、失败会说明”，不能只看演示图片识别成功。

记录样例指纹、格式、页数、是否扫描、机器 CPU／内存／系统版本、冷启动与缓存后耗时、峰值内存、关键文字和结构遗漏、引用定位。模型依赖首次准备时间与离线 OCR 识别时间分开测量，API 网络耗时与本地解析耗时分开记录。准确度、速度、安装体积与最低配置在结果出来后确定，不先编造指标。

这些测量不新增文件上传入口；测试中本地文件边界不变。预算提醒与生成上限仍为待确认建议项。
