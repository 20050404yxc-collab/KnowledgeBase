## 进入与重建环境

在项目根目录运行进入脚本，为当前 PowerShell 会话启用虚拟环境和已确认的缓存、模型路径；不会永久改系统环境变量。

简单说：新开终端后，先执行下面这条命令再开发。

```powershell
Set-Location D:\code\KnowledgeBase
. .\scripts\enter_dev.ps1
```

需要在相同 Windows x64／Python 3.13 平台重建时，先确保现有 Node.js／npm／Python 版本满足上表，再执行以下命令。已有环境无需再次安装。

```powershell
py -3.13 -m venv .venv
. .\scripts\enter_dev.ps1
python -m pip install --only-binary=:all: -r requirements-dev.lock.txt
npm.cmd ci --no-fund --no-audit
.\scripts\install_electron.ps1
python scripts/prepare_ocr.py
npm.cmd run check:env:node
npm.cmd run check:env:python
```

Electron 官方下载 ZIP 保存在 `D:\dev-tools\cache\electron`，解压后的运行时在项目 `node_modules\electron\dist`。安装脚本通过 GitHub 官方 API 获取发布文件并与 Electron npm 包内的 SHA-256 清单比较，校验失败即停止。Node.js 本次直连 `github.com` 超时，而 PowerShell 和 Node.js 均能访问 GitHub API；这不表示所有 GitHub 访问均失败，也不保证未来网络始终可用。

若 OCR 资源被清理，重新执行 `python scripts/prepare_ocr.py`；模型仍需通过记录的校验值。跨平台或更换 Python 大版本时，应重新评估 Windows 二进制包与锁定版本，而不是把本次环境视为通用锁文件。

上述环境准备证据保存在 [验证记录](../../../task-specs/20261020-01-personal-knowledge-agent/verification.md)，保留当时的验证范围。test0.03 的中文检索与后台生命周期已通过隔离桌面回归，见[存量代码整改](../工程规范/存量代码整改.md)；真实复杂文档质量、模型接口和干净机器安装仍未验证。
