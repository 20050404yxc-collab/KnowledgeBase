## 本轮需要重点阅读的内容

本轮先看[产品方案](个人知识库/产品方案.md)第 3.9 节：左侧多选，右侧生成和补充资料；一个项目一次提交后逐点核对并全部生成，常用／在学／归档只增加输入框和确认键，沿用探索设置。已按本次具体需求实施。

简单说：不用再逐点重复上传资料和点击生成；截图只用于理解布局，按钮文案不作为额外授权。

当前已按[项目编码与分层规范](工程规范/项目编码与分层规范.md)整理存量代码，采用进程职责边界、后台四层和前端功能模块，后续开发必须遵守。test0.03 是实际整改与验证；产品文档中的 test0.01 历史证据保持原始范围，本轮 API／模型交互已在相同代码基线增量实施。

产品方案说明搜索、带文档提问、自动收录、三条关联推荐和频率分区；技术设计说明本地数据、Python 后台、文档解析和 API 管理；实施与验收说明先验证哪些风险、如何判断功能真正可用。

通俗地说，先看“它怎么用”，再看“准备怎么做”，最后看“做到什么程度算完成”。

## 尚待确定的事项

本轮已确定 GPT 优先，并接入 DeepSeek、Claude、Grok 等主流模型；采用 A 平衡频率方案；文件地址仅限本地路径；验收基准为 Windows 11 x64、16GB 内存、无需独显。

简单说，模型方向、知识分区规则和测试电脑基准已经有结论，不再列为待选方案。

- 各供应商的实际官方／中转接口、协议、具体模型和向量模型配置。
- OCR 已完成首轮开源资料调研；RapidOCR＋ONNX Runtime 为优先验证候选，Docling 为复杂版面增强候选，尚未最终定库或实测。
- 扫描 PDF／OCR 是否必须首发交付、资源随包还是首次使用准备，以及旧 DOC 兼容范围。
- 用于解析、引用和安装验证的实际样例文件、具体机器与可测性能指标。16GB 是测试基准，不是已验证最低配置。
- 每日预算提醒和单次生成上限是否纳入首发。

以上事项不会被静默视为已确认。相关文档分别说明建议、影响和验证方式。
