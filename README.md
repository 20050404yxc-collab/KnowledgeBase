# 知序 · 个人知识库

当前版本：**test0.03**。这是 Windows 桌面开发测试版，采用 Electron + React / TypeScript + Python + SQLite。

本次已按[项目编码与分层规范](docs/确认页/工程规范/项目编码与分层规范.md)整改存量代码：React 按探索、知识、资料、接口和用量组织；Electron 分开窗口、IPC 与后台生命周期；Python 采用入口、应用、领域、基础设施四层，由装配点注入实现。相关说明见[存量代码整改](docs/确认页/工程规范/存量代码整改.md)，后续开发遵守根目录 [AGENTS.md](AGENTS.md)。已保留 API 编辑与模型选择；已增加安全 Markdown、本地检索、知识点目录与增量补充；本轮进一步支持切页继续任务、四页分层浏览、确认式重构及拓展自动分类。原知识、凭据身份和用户数据位置保留。

## 日志与排查

程序默认在当前数据目录的 `logs` 子目录保存详细日志。展开界面底部可查看数据目录；`2026-10-21-1-desktop.log` 记录界面与桌面宿主，`2026-10-21-1-worker.log` 记录后台各步骤；每次进程启动新建文件，两类分别按本地日期和当天序号命名。每条包含时间、会话／请求 ID、步骤、耗时和脱敏错误位置；每文件 5 MiB，超限时新建下一序号文件；启动及持续运行满一天后的首次写入清理最后写入时间严格超过 14 天的历史日志，当前文件保留。错误发生后按时间找到 `request_id`，在两组日志中搜索同一个 ID，可追踪失败前后的步骤。

简单说：问题复现后，打开日志目录，按一次操作的编号就能一路查到出错步骤；密钥、问题正文、资料和模型完整输出不会作为日志保存。详细字段、命令和限制见[日志与问题排查](docs/确认页/工程规范/日志与问题排查.md)。

## 启动

本机开发环境已准备。双击根目录的 `启动知序.cmd`，或执行：

```powershell
npm run build
npm start
```

开发时使用 `npm run dev`。首次克隆请先按照 [开发环境说明](docs/确认页/个人知识库/开发环境.md) 创建 `.venv`、安装锁定依赖和 Electron 运行时，然后构建。当前程序依赖项目内 `.venv` 和 `node_modules`，尚未提供独立安装包。

## 当前可用

- 知识新建、编辑、删除、中文关键词检索；常用 / 在学 / 归档自动计算，支持手动固定。
- 新增“知识库”总览；知识库、常用、在学、归档统一按多层知识树显示（如“编程语言 → C++ → STL → 容器 → vector”），各自保留筛选、展开、分页及阅读状态。
- 拆分、学习、拓展、批量生成和重构在切换页面后继续；全局任务条可返回或取消。保留单个生成流程，不支持关闭后续跑。
- 全库重构由双路分析正文与补充，逐组确认重复候选和保留点，再确认目录、完整原文提取稿及独立模型补充；默认不勾选内容更新。新问题与拓展自动归类。
- 拖入文档、选择文件或粘贴本地路径；读取 MD、TXT、DOCX、文字版 PDF，显示位置、引用摘录及解析局限。
- 附件默认仅用于本次会话；点击“保留”才将快照加入资料库。退出后清理会话副本，不修改用户原件。
- 本次文件、知识库及混合范围提问；先显示按主题分组的知识点目录，选中后再学习；无 API 或拆解失败仍能打开本地命中。
- 独立“本地检索”覆盖所有频率分区的标题、正文、主题、补充及已保留资料，每页 30 条，不调用模型。
- 正文及检索摘录安全渲染 Markdown 标题、列表、加粗、表格和代码；真实引用可点击，HTML／危险链接／远程图片不执行或加载。
- 配置 Responses、Chat Completions 兼容接口及 Anthropic Messages 协议；已保存接口可编辑，API Key 通过 Windows 凭据管理器保存且编辑时可留空保留。
- 获取或手动维护模型目录，可不设置默认模型；提问和关联拓展可在主界面选择模型与推理强度。实际模型兼容性仍须按供应商验证。
- 完整模型响应经结构和引用 ID 检查后按知识点收录；同一目录项重复点击复用已完成结果。不同主题可有同名知识。
- 后续提问的新内容可向已有知识生成补充，经预览确认才追加，原笔记保留；补充可独立编辑、删除、检索并保留模型与引用。旧 `question` 协议入口继续兼容原来的复用规则。
- 关联卡片优先展示最多两条相关旧知识，其余由模型提出拓展；点击拓展才生成。数量不足会明确显示。
- 调用记录包括成功、失败、取消和中断。接口未返回的用量显示“未知”；用户填写价格后按调用时价格估算，分币种统计。

简单说：先在本地写、查、读，配置自己的接口后再使用 AI 学习和积累功能。

## 目录与积累的用法

1. 只找旧内容：输入关键词，点击“本地检索”。不需要 Key，也不调用模型。
2. 理解新问题：选好范围、接口和模型，点击“拆解并学习”（或 Ctrl+Enter）。先得到按完整路径分组的知识点目录，原问题不会直接成为知识标题。
3. 选择知识点：已有候选直接读取本地；待学习项再点击“学习这个知识点”。也可勾选具体点或整类后串行生成；单项失败保留结果并继续，明确取消停止后续项。
4. 后续补充：重新提问，选中关联目标并点击“生成补充”，核对内容和归属后保存；有歧义时可独立保存。原有正文不会被覆盖。
5. 已保存知识的补充按时间展示，可单独编辑或删除；目录是本次会话状态，最多保留 24 份，重启后重新拆解，正式知识与补充仍然保留。

简单说：查找独立可用；学习按点进行；新内容作为补充积累在同一知识下。

“本地检索”按钮固定搜索全库。问题目录按选择的文件／知识库／混合范围检索和生成，其本地结果分页沿用该次范围；仅本次文件不会混入知识库。目录规划和每次学习分别产生调用记录，确认保存预览不再调用模型。归类与结论仍需人工核对，关键词可能漏掉同义表达。

已保存知识支持逐层细分。点击球体展开，下方“阅读本节点”打开该层正文；一个节点可以同时有正文和下级。整理位置每行填写一层名称（父级最多 64 层、每层 80 字），斜线属于名称，不作为分隔符。旧知识不会自动重新分类，需在重构预览中确认新位置。

简单说：STL 可以有自己的概述，也能继续进入容器、vector 和扩容机制。

## 重构知识库

“根据意见调整当前方案”会保留本次成功分析和已有目录，累积历次意见（可展开查看），在同一草案上继续修改；切页保留，关闭应用或丢弃后释放。每条意见最多 2000 字符，累计 6000 字符，超限保留旧方案并提示重新整理意见。

归类后主动比较同一完整父级路径内的知识内容，提出同一知识的合并结构；核对并确认目录后核验全文、融合重复定义与互补信息，最终选择完整融合稿再保存。仅相关知识保持独立，来源与手工原件保留。语义比较会增加模型调用，长文跨批重复仍需人工核对；真实模型质量尚未验收。

在“知识库”选择接口、模型后点击“重构知识库”。两个应用内分析代理从快照两端领取来源，每来源一次轻量概览，原文取样总计最多 7000 字符，概览最多 2400 字符；可查看抽样与未读范围。先按概览提出目录，不在结构确认前重写正文或做全文重复核验。失败暂停，点击继续才重试；切页继续，退出后未确认草稿不恢复。

核对新旧目录、归类理由与来源归属，可调整标题及位置；未选择的重复候选默认独立。明确拟合并的保留点、名称、目录与分区后确认结构，才核验相关全文，冲突退回结构审核。随后模型按确认结构逐段重新组织全部正文、补充与历史来源，保留限定、示例和引用。重构正文不设业务总字符上限；单次模型、超时、传输和机器资源限制仍有效。长正文与差异分段查看，长补充点击加载，编辑本段时保留其他段并在完整上传及版本检查后原子保存。

最后核对并选择内容更新才正式保存。手工或编辑过的正文及原补充保持保护，整理稿另附补充；未编辑机器正文可选择替换并保留原版本。合并必须整体接受完整重组稿，无合并可仅应用目录；保存创建恢复点并原子更新映射、目录、正文及索引。程序保证输入段覆盖和原引用标记保留，不能自动证明模型语义无遗漏，仍需用户核对。

最后确认才原子保存并更新检索索引；旧 ID 解析到保留点，检索保留全部来源而不重复展示合并组。在知识详情的“查看整理／合并前原文（只读）”中可分页查看原记录。暂不支持删除已合并组，也不保证真实模型质量或大库性能。

简单说：先看目录，再看改文，最后确认才保存；切到别页也会继续。

保存前自动创建数据目录内的 `before-restructure-<UUID>.sqlite3` 恢复点。预览期间库中新增、删除或编辑会使旧方案过期，需要重新规划；失败整体回滚。草案只保留当前后台会话的一份，不承诺退出后恢复。恢复时先关闭应用并备份整个数据目录，在隔离副本中将恢复点复制为 `knowledge.sqlite3` 后确认内容；不要在运行中覆盖数据库或遗留 WAL/SHM 文件。恢复点仅覆盖数据库，资料副本和系统凭据需按完整数据备份管理。

## API 使用

在“API 配置”中填写名称、**实际协议**、基础地址并填写 API Key；获取模型列表或手动添加后，可指定默认模型，也可以留空。编辑现有接口时 Key 留空可保留原凭据。基础地址包含供应商要求的前缀，例如 `https://api.openai.com/v1`；不要填写完整的 `/responses` 或 `/chat/completions` 路径。远程地址需要 HTTPS，本机服务可使用 HTTP。获取模型只请求模型目录，不测试生成。

主界面可选择此接口的目录模型和推理强度；选择具体模型覆盖本次请求但不修改默认值。Responses 使用 `reasoning.effort`，Chat Completions 使用 `reasoning_effort`；Anthropic 当前只使用自动强度。非默认模型费用显示未知。兼容端和具体模型是否支持这些档位尚未实测。“测试连接”会发起真实模型调用，可能产生费用。开发验收使用本机模拟接口，没有调用付费服务。主流模型品牌不代表协议相同，请按实际服务填写；真实 GPT / DeepSeek / Claude / Grok 兼容性仍需使用你的配置验证。生成模型不会自动启用向量能力。

## 数据与支持边界

默认数据位于 Electron 的 Windows 用户数据目录，确切路径可在“设置 → 存储与日志”中查看或打开；SQLite 正文及资料副本位于该目录，API Key 存于 Windows 凭据管理器。备份前先关闭应用，复制完整数据目录；凭据不包含在普通目录备份内。开发测试可通过 `KB_DATA_DIR` 指定隔离目录，测试脚本不会操作正式数据。此前知识目录将 SQLite 从版本 2 增量到 3，升级前通过 SQLite 备份 API 创建 `before-knowledge-topics-v3.sqlite3` 一致性备份；更早的模型目录升级保留 `before-model-catalog-v2.sqlite3`；升级失败会停止写入并提示保留数据目录和备份，排查后再重试。本轮从 schema 3 升级至 4，新增来源到保留点映射、原文版本及追溯记录；升级前创建带唯一标识的 `before-knowledge-merges-v4-*.sqlite3` 一致性备份。迁移失败回滚并停止打开；高于支持版本的数据库拒绝打开。正式数据迁移尚未验收。

测试版单文件上限 50MB，PDF 200 页，一次最多 20 个附件，单次模型文字上下文约 28000 字；补充生成的已有正文和新证据共用该预算，覆盖不全会显示提示。超限全文总结会拒绝发送并要求拆分，尚无分层全文总结。四页已有知识树覆盖全库或本区，分类与叶子每批 50 项，不受旧列表 200 条上限限制；独立检索覆盖全库及补充。FTS5 不可用时提示完整分批扫描回退。MD 保留原始文本，DOCX 使用正文块位置；图片、页眉页脚及复杂表格版式可能遗漏。PDF 无文字页面会明确提示，不做 OCR。

**尚未完成：**OCR、旧 DOC、语义向量索引、概念级同义去重、复杂文档质量验收、推荐质量实测、完整故障注入、运行时资源测量和干净机器安装包验收。模型校验确认结构与引用 ID 有效，不能证明每个结论都被引用支持；实际内容仍需核对。当前阅读器安全渲染 Markdown，编辑器保留原文，不执行来源 HTML。

## 设置与用量

侧栏进入“设置”：API 配置保留原有接口、模型发现、手动模型目录和编辑能力；“存储与日志”显示当前数据目录、数据库、资料副本和日志目录，并支持打开固定目录。路径只读，当前不迁移数据或修改存储位置。密钥仍由 Windows 凭据管理器保管。

在接口表单选择“计价模型”，按需勾选“添加模型价格”，分别填写输入／输出每百万 token 单价及币种。每个模型独立配置；留空为未知，0 为显式免费。只有两侧用量和两侧价格齐全才估算费用，未定价模型不会借用其他模型价格。修改配置不重算已有调用记录。

“用量统计”汇总全部历史输入／输出 token，缺失用量时显示“已知小计”和缺失记录数；费用分币种列出可估算及未知数量。明细保留最近 500 条，汇总不受此上限影响。估算不是供应商账单，失败和取消尝试也保留真实返回用量。

模型价格采用 schema 4→5 增量迁移；创建唯一 `before-model-prices-v5-*.sqlite3` 一致性备份后才建表，旧价格只迁到旧默认模型。失败回滚并停止打开，正式用户库迁移未验收。
