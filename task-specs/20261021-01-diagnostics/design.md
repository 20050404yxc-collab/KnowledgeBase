# Design

Host: asynchronous serialized `DiagnosticLog`, 1024-entry queue, dated daily-index segments, fixed fallback warning, flush after owned worker shutdown. Initialization occurs only after the single-instance lock. `YYYY-MM-DD-N-desktop.log` includes a session UUID passed to the worker via `KB_LOG_SESSION`. Renderer/preload send only validated typed metadata over `kb:diagnostic`, limited to 600 messages/minute; host reconstructs allowed fields. No new worker operation or schema change.

Worker: package-level diagnostics is a technical cross-cutting utility independent of application/infrastructure implementations. A safe RotatingFileHandler subclass owns `YYYY-MM-DD-N-worker.log` with custom nondeleting byte-based rollover; ContextVar tracks request and span context across awaits and to_thread. Explicit `@traced` decorations wrap selected boundary functions without inspecting args/results. `step` propagates exceptions and cancellation unchanged. Error chains contain types, source basenames/functions/lines and numeric system codes; only fixed exact-match approved reasons include text. Third-party root logging remains unchanged. Sensitive numeric fields from provider metadata are type-checked before serialization.

Instrumentation covers service assembly, protocol dispatch and summaries, storage reads/writes, credential access boundaries, model attempts/accounting/HTTP/first chunk, model discovery, public-project HTTP, document validation/copy/parse/cleanup, question lock wait, evidence/reuse/fallback/validation/capture, topic planning/review/learning and library restructuring. Domain rules remain free of external I/O.

Normal shutdown settles worker resources, writes final worker entry, waits host queue and quits. Diagnostic I/O errors use fixed stderr/console text rather than raw logging error fallback. Unknown worker stderr is counted, never persisted verbatim. Abrupt crashes may lose queued host records. Build output may give bundled TS locations; Python logs retain original source function and line. No sourcemap publication or native crash collector is introduced.

Revision 2 allocation uses exclusive create and retries only name collisions. Cleanup is process-local, whitelist-based, strict mtime expiry, startup plus lazy daily write checks; no timer/thread is added. Active files and links are skipped; permission failures warn without aborting writes. Worker handler lock serializes threaded emission/rollover. Host serialized queue retains asynchronous I/O and flush ownership. Tests and UI fixture readers aggregate dated segments in numeric order; restart UI assertions verify old file contents remain unchanged. Settings text and README match retention; no configuration or dependency addition.
